# v4.11 → v5 迁移指南（阶段 0-7 产出）

> 状态：文档已产出；**待 v5 首个 Release 发布后由用户按此实测**（0-7 的最终验收）。
> 原则：v4 的实例原样保留，v5 不改写旧实例；数据用复制而非移动。

## 一、v4 用户当前状态

- 更新器是 `update_modpack.ps1` + `.bat`，放在**版本文件夹**里（如 `.minecraft\versions\红石镇客户端\`）。
- 版本状态：`RSTC_version.txt` 存 Release Tag（如 `v20260712-103024`）；备份在 `_modpack_backup\`。
- 实例里 `mods/`、`config/` 等由 v4 用 `robocopy /MIR` 同步。

## 二、迁移步骤（v5 发布后）

1. **备份**：把整个 `.minecraft\versions\红石镇客户端\` 复制一份到 `.minecraft\versions\红石镇客户端-v4备份\`（玩家存档也在里面，必须先备）。
2. **下载 v5**：从 `RSTC-Updater` 仓库 Release 下载 v5 的发布包（exe + `.bat`，按 §2.1 的产物形态）。
3. **安装到新目录**：运行 v5 → 「安装到新目录」→ 选择 `.minecraft` 根 → 实例名默认「红石镇客户端」（6.0）；v5 会装 26.3 + Fabric + 整合包内容。
4. **迁移玩家数据**：v5 → 「从旧实例迁移」→ 源选步骤 1 的 v4 实例 → 勾选 存档/截图/地图/DH 缓存/游戏设置与键位 → 执行。
5. **启动**：完成页会给出实例路径与启动器提示；PCL2/HMCL 里选新实例启动。
6. **确认**：旧实例保持原样可回退；确认新实例可玩后再清理旧实例（可选）。

## 三、回滚

- 新实例出问题：删除 `versions\红石镇客户端\`（v5 新装的目录），旧目录未动。
- 迁移写入了数据：v5 迁移是复制+校验，源未变；目标可整目录删除重来。
- 玩家存档兜底：步骤 1 的整目录备份。

## 四、v4 自更新的已知坑（必须公告）

v4.11 的 `Get-UpdaterRelease()` 要求最新 Release **同时含 `update_modpack.ps1` 与 `update_modpack.bat`**，否则返回 null 并显示「无法获取更新器版本信息」。因此：

- **首选**：v5 的 Release 同时放两个占位资产（`update_modpack.ps1`/`.bat` 只打印"v5 已改为独立程序，请下载 xxx"），这样 v4 用户点自更新能拿到引导；
- **或**：在仓库 README 与群公告里给出手动下载步骤，并说明 v4 不会自动升级。

## 五、验收（待用户实测）

| 步骤 | 期望 | 通过阈值 |
|---|---|---|
| 按步骤 1-3 安装 v5 | 新实例目录生成，旧实例未被改动 | 旧实例哈希不变 |
| 按步骤 4 迁移 | 存档/截图等出现在新实例，源不变 | 逐文件比对 |
| 启动新实例 | PCL2/HMCL 可启动，mod 生效 | 游戏内可见 |
| 回滚演练 | 删除新实例目录后旧实例仍可启动 | v4 实例启动成功 |

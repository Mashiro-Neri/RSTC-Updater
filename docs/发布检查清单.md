# 发布检查清单（v5 发布器任务）

> 这是给**发布 6.0 整合包 / v5 更新器**时用的清单；更新器代码不实现发布，只依赖这些契约。发布前逐项打勾，并把结果贴在 release notes 里。

## A. 6.0 整合包（`Mashiro-Neri/Redstone-Town-Client_update_modpack`）

- [ ] 目标 MC 固定 `26.3`；Fabric `0.20.1`
- [ ] zip 根目录有 `modrinth.index.json`：`versionId`（如 `6.0`）、`dependencies.minecraft = 26.3`
- [ ] 所有文件在 `overrides/` 下（更新器只应用 `overrides/`）
- [ ] **发布包内不得包含 `PCL/`**（用户硬要求）：`overrides/PCL/` 及其子项全部移除（PCL2 自己的配置由更新器写 `versions/<实例>/PCL/Setup.ini`，不发布）
- [ ] `overrides/mods/` 下 mods 数量与清单一致；`config/` 不含个人存档/键位
- [ ] 资产命名 `RSTC-<版本>.zip`（如 `RSTC-6.0.zip`），Release tag 与版本一致（如 `v20261112-xxxxxx`）
- [ ] GitHub Release digest（sha256）可用（更新器强校验，缺失会拒绝下载）
- [ ] 校验命令通过：
      `pwsh -File scripts\release\validate-pack.ps1 -ZipPath <RSTC-6.0.zip> -ExpectedMinecraft 26.3`
- [ ] （可选）`pack-meta.json`：`{"minecraft":"26.3"}` 作为独立资产，便于更新器在下载前判断

## B. v5 更新器（`Mashiro-Neri/RSTC-Updater`）

- [ ] Release 资产名 `RSTC-Updater-<ver>.zip`（自更新按此前缀匹配；不含此前缀时自更新会安全降级为"无可用更新"）
- [ ] zip 根目录含 `RstcUpdater.exe` + 16 个依赖 DLL + `启动.bat`；**不含 `PCL/`**
- [ ] tag 形如 `v5.0.0`（自更新用数值比较：`5.0.0 > 4.11`）
- [ ] 校验命令通过：
      `pwsh -File scripts\release\validate-pack.ps1 -ZipPath <RSTC-Updater-5.0.0.zip> -Kind updater`
- [ ] Release notes 写清：v4 用户如何升级（v4 自更新资产名不同，需按迁移指南手动覆盖或发布器同时保留 v4 兼容资产）
- [ ] 发布后实测（用 `docs/验收指引.md`）：
  - [ ] `--check-self` 提示 `RSTC-Updater-5.0.0.zip` 可用
  - [ ] 确认替换：程序退出→自动替换→重启后版本为新版本（E1）
  - [ ] 失败回滚：替换时占用 `RstcUpdater.exe`，应回滚旧版并重启（E2），`%TEMP%\rstc-selfupdate-error.txt` 有记录
  - [ ] `--status` 显示新版本号

## C. 发布后联合验收（0-7 关闭条件）

- [ ] 空目录 `RstcUpdater.exe` 菜单安装：在线下载 6.0 → 完成页路径正确
- [ ] `--status` 关键文件全 OK；实例里**没有** `PCL/`（更新器跳过）
- [ ] PCL2 与 HMCL 分别启动新实例，mods 生效（A1b 的双启动器前提）
- [ ] v4→v5：按 `requirements/v4到v5迁移指南.md` 操作，新实例 `红石镇客户端 6.0`，旧实例保留；回滚只删新实例
- [ ] 再次安装/更新提示"已是最新"；更新保留存档/设置；删除清单可勾选保留
- [ ] 证据归档：`evidence/acceptance/<日期>/`（截图 + 日志路径）
